AI 编程通识课 · 模块 2 看懂代码的骨架
第 07 节

组织：模块、导入、类，以及读代码的方法

1 一句话结论
大程序拆成小文件分工，读代码先抓主干再抠细节。

2先打个比方：零件、总成与整车

一辆车不是一整块铁，是几万个零件先装成发动机、变速箱这样的总成，总成再装成整车。程序也一样：小段代码先封成函数，函数按活分进不同文件（模块），文件之间互相调用，最后拼成一个能跑的程序。你看装配图不会盯着一颗螺丝看，读代码也一样，先看总成。

图：函数是零件，模块是总成，程序是整车

3正文

模块：按活分文件。程序一大，就按职责拆成多个文件，每个文件管一摊事，这叫模块（module）。好处很实际：改录制功能时不用碰刷写代码，AI 定位也快，不容易误伤别处。

导入：开工先领零件。要用别的模块里的东西，先写一句 import（导入）把它请进来。代码开头那几行 import 就是这个文件的「领料单」：扫一眼，就知道它干活靠谁。

import把模块请进来
领料单写在文件开头
先看它就知道依赖谁

类和对象：图纸和实物。类（class）是图纸，规定这类东西长什么样、能做什么；对象（object）是照图纸造出的实物。比如「报文」是图纸，每一帧真实报文是一个对象，数据各不同，规矩都一样。理解到这层就够用了。

类（图纸）对象（实物）
是什么定义和规矩，只有一份照着造出的每一个
报文例子「报文有 ID 和数据」第 1 帧、第 2 帧……

注释和读代码四步法。注释（comment）是写给人看的说明，电脑执行时跳过它。读陌生代码按四步走：看名字猜职责，看输入输出，顺主干看流程，最后把抠不懂的段落发给 AI 逐句解释。

1看名字：文件和函数叫什么，猜它管什么
↓
2看输入输出：喂进去什么，吐出来什么
↓
3看主干：顺着主要流程走一遍，先不抠细节
↓
4问 AI：把卡住的段落发给它逐句解释

4对应到你的项目：CANLink 的分工

你的 CANLink 就拆得很清楚，网页不是一个大文件，而是按活分成几个模块：app.js 管主界面，diag.js 管诊断，flash.js 管刷写，recorder.js 管录制，slcan.js 管和 CAN 盒子说话。

这正是「模块」的样子：哪个功能出毛病，先定位到对应文件，就是顺着总成找零件。下面读代码的那一小段，就来自 app.js——主界面里负责「把文件下载下来」的一个零件。

5和 AI 协作时怎么用

可以这样说「先告诉我这个功能在哪个文件里，只改那个文件，其他文件不要动。」
可以这样说「把这段代码逐行用中文解释一遍：先讲它整体干什么，再讲每一行。」
别这样说「把整个项目重构一下，整理干净点。」——重构动的是整体结构，范围最难控制，没有明确收益不要轻易开这个口。

7小测（选完立刻看对错）

1. 一个文件开头的几行 import，最能告诉你什么？
解析：import 是领料单，扫一眼就知道这个文件依赖谁、和谁配合。
2. 按「类是图纸、对象是实物」的说法，一帧具体的报文数据是？
解析：「报文长什么样」的定义是图纸（类），每一帧真实报文是照图纸造出的实物（对象）。
3.（情景）AI 说要把 recorder.js 里的导出函数挪到一个新文件里。这件事的性质是？
解析：挪函数是结构调整，引用它的地方一个都不能漏，验收时要逐个功能点一遍。
4. 拿到一段完全陌生的代码，第一步先看什么最有效？
解析：四步法的第一步是看名字抓职责，先有全局，再抠细节。
5. 代码的注释写错了、和实际代码对不上，会怎么样？
解析：注释电脑不执行、也不校验；过时的注释比没有注释更坑人。

8读代码：CANLink 里真实的一段

下面这段 JavaScript（网页用的编程语言）原样摘自 CANLink 的 app.js，一行没改：你在 CANLink 里点「导出」下载文件时，跑的就是它。点任意一行，看这一行在干什么。

function downloadFile(f) {
const a = document.createElement('a');
a.href = URL.createObjectURL(f);
a.download = f.name;
document.body.appendChild(a); a.click(); a.remove();
setTimeout(() => URL.revokeObjectURL(a.href), 60000);
}
点任意一行，这里会显示这一行的中文解释。
