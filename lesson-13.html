第 13 节

数据存在哪

1 一句话结论
记录进数据库按格子存，大文件进档案室按件存。

2先打个比方：表格与档案室

单位里记信息有两种地方。一张是 Excel 表格：行列分明，想查「谁、哪天、多少」一筛就出来。另一处是档案室：一盒盒文件按编号上架，要的是整件拿走、整件放回。程序存数据，也正是这两派。

图：一派按格子记账，一派按件存档

3正文

数据库，把数据摆进格子。数据拆成一张张表（table）：一行是一条记录（record），一列是一个字段（field）。照片表里，一行就是一张照片：编号、所属区域、日期，各占一格。格子先定死，查起来才快、才不乱。

id 编号region 区域date 日期
11A14 重庆2026-09-18
12B07 武汉2026-10-02

日常操作，就四个动作。增：加一条记录；查：按条件捞出来；改：更新某一条；删：去掉某一条。合起来叫 CRUD，就是四个英文词的首字母。AI 说「加个查询接口」，就是给「查」多开一个入口。

增Create
查Read
改Update
删Delete

指挥数据库，用 SQL。SQL（Structured Query Language，结构化查询语言）是操作数据库的专用语言，长得像英文句子。第 8 块有四行真例子，点开逐行看——日常增删改查，基本就是那几句。

动作SQL 关键词大致意思
查SELECT把符合条件的行捞出来
增INSERT INTO往表里加一行
改UPDATE改掉某几行的内容
删DELETE去掉某几行

大文件，不进数据库。照片、视频的本体又大又多，塞进数据库会让它又慢又挤。常见分工是：本体放文件存储，按文件名一件件存取；数据库里只留一行小记录，写清它存在哪、属于谁。

数据库文件存储
存什么一条条结构化记录照片、视频等文件本体
怎么找按条件筛：某区、某天按文件名整件拿

4对应到你的项目：相册是文件存储派

相册没有用数据库。它全部的结构化记录写在一个 album.json 文件里，照片本体也是一个个文件，都躺在 COS 上；程序自己读文件、改文件、再存回去。数据量不大、就两个人用，这样最简单，也足够。

如果换成数据库，会是另一副摆法。区域拆一张表、照片拆一张表，照片表里多记一列区域编号，两张表靠编号关联：查「重庆的所有照片」，就是拿着编号去照片表里筛。等到人变多、查法变花哨，才轮到数据库上场。

所以听到 AI 说「先用文件存就行」，别觉得它在偷懒——对得上规模的选法，才是好选法。

5和 AI 协作时怎么用

可以这样说「这些数据准备存数据库还是存文件？为什么这么选，先说理由。」
可以这样说「删数据是真删还是先标记？误删了能不能找回？」
可以这样说「以后要按日期、按区域筛数据，现在这个存法筛起来快不快？」
别这样说「数据你随便存一下。」——存法决定了以后查得快不快、丢了能不能恢复，不能随便。

7小测（选完立刻看对错）

1. 在数据库的表里，「一行」通常对应什么？
解析：一行是一条记录（比如一张照片的全部信息），一列才是一个字段。
2.「把这条数据的日期改一下」，属于 CRUD 里的哪个动作？
解析：改已有记录的内容，就是 Update；对应 SQL 里的 UPDATE。
3. 照片本体一般不直接塞进数据库，主要因为？
解析：常见做法是本体放文件存储，数据库里只记一行「它在哪、属于谁」。
4.（情景）AI 说：「我把相册数据从 album.json 换成数据库了。」你最该先问什么？
解析：换存法先问收益对不对得上规模，再问迁移和备份；为换而换，只会添乱。
5. 区域表和照片表要「对上号」，靠的是什么？
解析：照片表里记上区域编号，就能顺着编号找到它属于哪个区域——这叫关联。

8读代码（点一行，看一行）

四行 SQL，正好对应增、查、改、删。点任意一行，看它在指挥数据库做什么。

SELECT * FROM photos WHERE region = 'A14';
INSERT INTO photos (region, date) VALUES ('B07', '2026-10-02');
UPDATE photos SET date = '2026-10-03' WHERE id = 12;
DELETE FROM photos WHERE id = 12;
点上面任意一行，这里会显示这一行的意思。
