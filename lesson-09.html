前端、后端、数据库：三件套

一句话结论
前端管脸面，后端管干活，数据库管记账。

2先打个比方：一家餐厅

一个网页应用就像一家餐厅。大堂是客人能看到、能坐的地方；后厨关着门，客人不进去，但菜都是在里面做的；仓库不上菜也不做菜，只管把食材存好、要的时候取出来。三方配合，一顿饭才上得了桌。

图：三件套的分工——对应英文 frontend / backend / database

3正文

前端：你看得见的那一层。页面长什么样、按钮在哪、点了有什么反应，都归前端管。它运行在你的浏览器里，由三种代码合作：HTML（HyperText Markup Language，超文本标记语言）搭骨架，CSS 管打扮，JavaScript 管动作——这三个词下一节细讲。

HTML骨架：有什么
CSS打扮：长什么样
JavaScript动作：能干什么

后端：关着门干活的那一层。核对身份、处理数据、调用别的服务，最后把结果递回给前端。它运行在服务器（server）上——一台一直开着的电脑。你看不见它，只能通过前端「上菜」知道活干完了。

前端后端
在哪跑你的浏览器里服务器上
负责什么显示和交互逻辑和处理
打个比方服务员和菜单厨师和灶台

数据库：只管记账的那一层。它只做两件事：存、取。像一本结构严谨的电子账本，每条数据放在固定的格子里，查得快、不会乱。它不负责思考——「这笔该不该记」是后端说了算，它只负责记好。

一次点击的完整旅程。以在相册里传一张照片为例：你在前端点「上传」，前端把照片打包成请求（request）发给后端，后端检查加工后存进数据库，数据库回一句「存好了」，前端随即把新照片显示出来。一去一回，就是一次请求与响应（response）。

4对应到你的项目：旅行相册

你的旅行相册（现行代码在 muse-letters 仓库的 album 目录）是个特别好的例子，它说明三件套分的是职责，不是机器：

前端，就是全部。相册托管在 GitHub Pages 上，是一堆静态网页文件；界面和操作逻辑都由浏览器里的 JavaScript 完成，没有别的程序在别处替它显示。

后端，没有自己的。按规矩「干活」该归后端，但相册没有一台服务器在跑后端程序：密码校验、编辑锁、版本比对这些逻辑也在浏览器里跑；真需要「有个地方办事」时，网页直接调用腾讯云 COS（Cloud Object Storage，对象存储）的接口。

数据库，也没有数据库软件。相册的全部数据是一个叫 album.json 的文件，照片本身也是文件，一起躺在 COS 的私有存储桶里，由网页直接读写——对象存储顶了「仓库」的班。

所以以后 AI 跟你说「后端」时，可以先问一句：这个职责现在是谁在担——我们自己的服务器，还是某个云服务？

5和 AI 协作时怎么用

可以这样说「这次只改前端的显示，不要动数据存取的部分。」
可以这样说「这个功能要保存的数据，准备放在哪、用哪种形式存？先说方案我再确认。」
可以这样说「改完了告诉我：动的是前端、后端还是数据，分别改了哪些文件。」
别这样说「把相册改一下。」——没说改哪一层、要什么效果，AI 只能猜，很容易改错地方。

7小测（选完立刻看对错）

1. 你在相册里点「删除照片」，这张照片真正被删掉，动作最终落在哪一层？
解析：前端只是把你的意图发出去；数据真正的增删，发生在存数据的那一层（相册就是 COS 里的文件和 album.json）。
2. AI 说「这次是后端改动，前端不用动」，最可能的意思是？
解析：后端管逻辑、前端管长相。逻辑改了，界面可以原样不动——这也是为什么有些更新你「看不出变化」。
3. 旅行相册没有自己的后端服务器，它靠什么把照片存下来？
解析：相册的网页拿到你用密码解开的密钥，直接读写 COS 私有桶——云服务顶替了后端和数据库的存取职责。
