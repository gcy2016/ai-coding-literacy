文件、路径和项目结构

1 一句话结论
文件靠扩展名认身份，靠路径找位置。

2先打个比方：文件柜与门牌号

单位的档案室里，资料装进一个个档案袋，档案袋按类别塞进文件柜的抽屉，每个抽屉贴着标签。电脑里一模一样：文件是档案袋，文件夹是抽屉和柜子。再给每个位置编上门牌号——哪栋楼、哪层、哪间——找任何一份资料，照着门牌号就能走到。电脑里的「门牌号」就叫路径。

图：文件、文件夹、路径，各管一件事

3正文

文件和扩展名。代码、照片、数据，在电脑里都以文件（file）的形式存着。文件名最后的后缀叫扩展名（extension），是文件的身份证：.py 是 Python 代码，.json 是数据，.md 是说明文档。看扩展名，先猜出这是什么。

扩展名是什么
.html网页文件
.js / .pyJavaScript / Python 源代码
.json数据文件
.mdMarkdown 说明文档
.pdf正式文档

文件夹和项目结构。文件不会散着放，而是装进文件夹（folder）分门别类。一个项目就是一个总文件夹，里面通常有说明文档、源码、数据和测试。AI 嘴里的「项目根目录」，说的就是这个总文件夹本身。

说明文档README：项目说明书
源码真正干活的代码
数据与测试材料和查错的

路径：文件的门牌号。路径（path）写明文件住在哪。绝对路径（absolute path）从最顶层写全，地址完整、不会认错；相对路径（relative path）从你当前的位置出发，只说「往前两间」。两种写法，可以指同一个文件。

绝对路径相对路径
写法/home/user/项目/data.json../data/data.json
好处在哪都指同一处短，跟着项目搬家也不怕
风险换台电脑可能失效起点不对就指错地方

为什么这和你有关。AI 干活时满嘴都是路径：它说「改了 docs 里那个文件」，你得知道动的是哪一份；它说「文件找不到」，多半是路径写错了，不是文件真丢了。看懂路径，验收时才对得上号。

4对应到你的项目：就看这门课

这门课的仓库（ai-coding-literacy）就是现成的例子。你现在看的课就住在这里，顶层摊开是这么几样：

index.html课程首页
lesson-09.html一节课的页面
outline.pdf课程大纲
AI_TEAM.md / CLAUDE.md给 AI 看的说明文件

CANLink 仓库分得更细。docs/ 文件夹放网页应用，test/ 放自测脚本，firmware/ 放固件源码——一个文件夹装一类东西，找什么先想它该在哪类里。

认扩展名就能认个大概。这个项目里：.md 是 Markdown 说明文档，.json 是数据文件，.js、.py 是源代码。AI 报文件名时，你先看后缀，心里就有数了。

5和 AI 协作时怎么用

可以这样说「你刚才改的文件，给我完整路径，我去仓库里对一下。」
可以这样说「先讲一遍这个项目的结构：每个文件夹各放什么。」
可以这样说「新建的文件放哪个目录？说清了再动手，别随手扔在根目录。」
别这样说「那个文件你改一下。」——项目里同名的文件可能有好几份，AI 很容易改错一份。

7小测（选完立刻看对错）

1. 看到一个文件叫 report.json，它最可能是什么？
解析：.json 是数据文件的扩展名，里面装的是结构化的数据，不是代码也不是图片。
2. 扩展名的作用是？
解析：扩展名是文件的身份证。系统靠它决定用什么方式打开，你靠它先猜出文件是干什么的。
3. AI 说「文件在 ../data 目录下」，它用的是哪种路径？
解析：带 .. 的是从当前位置出发数步数的写法，是相对路径。换个起点，它指的地方就跟着变。
4.（情景）程序报错「FileNotFoundError: data.json」（找不到文件），最可能的原因是？
解析：这类报错绝大多数是路径对不上：名字拼错、放错目录、相对路径的起点不对。先查路径，再怀疑文件丢了。
5.（情景）你让 AI 把新章节放进仓库，验收时最先确认什么？
解析：先对位置和名字。放错目录、起错名，内容写得再好也等于没交付。
