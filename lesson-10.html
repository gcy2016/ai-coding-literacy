AI 编程通识课 · 模块 3 一个网页应用是怎么组成的
第 10 节

前端：HTML、CSS、JavaScript

1 一句话结论
HTML 搭骨架，CSS 管样子，JavaScript 管动作。

2先打个比方：盖房子

一个页面像一间房。先立骨架：梁柱墙体，决定有几个房间、门开在哪。再搞装修：墙面颜色、地板、家具，决定好不好看。最后装电器：灯能亮、空调能转，房子才「活」起来。前端三件套，干的正是这三摊事。

图：先有骨架，再装修，最后通电能动

3正文

HTML 管结构。它决定页面上有什么：一级标题、一段话、一张图、一个按钮，各就各位。它只管内容和结构，不管好不好看，也不管点了会怎样。页面源代码里那些尖括号标签，写的就是它。

<h1>一级标题
<img>一张图片
<button>一个按钮

CSS 管样子。同一个按钮，HTML 只说「这是一个按钮」，CSS 说「它要是蓝的、圆角、字 16 号、离左边 10 像素」。改配色、调间距、挪位置，动的都是这层，功能一点不受影响。

同一个按钮 · 打扮 A同一个按钮 · 打扮 B

JavaScript 管动作。点了上传，它去读文件、发请求；数据回来，它把新照片画到页面上。关弹窗、验表单、算结果，凡是「动起来」的部分都是它干的。第 05、06 节学的变量、判断、循环，主要就写在它里面。

框架和开发者工具。框架（framework）是现成的半成品套装，React、Vue 最有名：等于请了装修队加预制件，盖得快，但要按人家的规矩来。浏览器自带的开发者工具（DevTools）能看元素、看请求、看报错，是你自己验货的放大镜。

管什么改它时的效果
HTML结构：有什么多一个按钮、少一段话
CSS样式：长什么样换颜色、调大小、挪位置
JavaScript行为：能干什么点了有反应、数据会更新

4对应到你的项目：旅行相册

相册没有用任何框架。仓库里只有几个工具包文件（处理照片的、连 COS 的），界面全是原生 JavaScript 一行一行写的。好处是简单直接，不用追着框架升级跑；代价是复杂交互得自己多写些代码。

旅行树就是三件套分工的现成例子。树的颜色由 css/app.css 里一组颜色变量统一控制，想换配色改变量就行，这是 CSS 的活；树怎么画出来，写在 js/tree-view.js 里；每根树枝往哪长的几何计算，在 js/tree.js 里——后两件都是 JavaScript 的活，一个管「画」，一个管「算」。

以后 AI 说「这个简单，不用上框架」，你就知道它在省哪份事；说「得改样式变量」，你也知道它只动样子、不碰功能。

5和 AI 协作时怎么用

可以这样说「这个改动只改样式（CSS），还是要改逻辑（JavaScript）？先说清再动手。」
可以这样说「先别引框架，原生写法做，简单优先；真需要时再跟我说理由。」
可以这样说「按钮点了没反应，帮我查 JavaScript 那层，顺便说说开发者工具里报了什么错。」
别这样说「页面不好看，你整体优化一下。」——没说哪不好看、要什么效果，AI 只能乱改，越改越乱。

7小测（选完立刻看对错）

1. 想把页面上的按钮从蓝色改成绿色，该动哪一层？
解析：颜色、字号、间距都是样式，归 CSS 管，功能不受影响。
2. 按钮在页面上看得见，点了却没反应，最该先怀疑哪一层？
解析：按钮在、样子正常，问题在「点了会怎样」这层，也就是 JavaScript。
3. AI 说「我用 React 把这个页面重写了」，意思是？
解析：React 是前端框架，说的是「怎么搭页面」，和配色、存数据都不是一回事。
4.（情景）AI 回复：「页面结构没问题，是样式文件里一个颜色变量写错了，我改 CSS 就行。」你该怎么接？
解析：问题定位在 CSS，就只动那一层。改动面越小，越不容易顺手改坏别的地方。
5. 想看「这个网页刚才发了哪些请求」，开发者工具里该看哪块？
解析：Network 面板按时间列出每个请求和它的结果，下一节讲状态码时就靠它。
