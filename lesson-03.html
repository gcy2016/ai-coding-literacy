第 03 节

终端：AI 为什么总在敲命令

1 一句话结论
终端就是用打字给电脑下命令的地方。

2先打个比方：点菜与喊话

平时用电脑像在餐厅点菜：菜单（图形界面）上有什么你点什么，点不了菜单之外的东西。终端像直接冲后厨喊话：没有菜单，你说什么厨师做什么，快是快，但喊错一句，端出来的可能就是另一道菜。AI 是熟客，它知道每道「暗语」怎么喊，所以总爱走喊话这条路。

图：图形界面（GUI）与终端（terminal），两种操作电脑的方式

3正文

命令行是什么。命令行（command line）就是一个打字下命令的窗口：你敲一行字，电脑照着做，再把结果以文字回给你。AI 总在敲命令，是因为不少活压根没有按钮可点；就算有，敲命令也比点十几下鼠标快、还准。

你敲一行命令
电脑做照着执行
回给你文字结果

命令的结构：命令名＋参数。一条命令的长相很规整：先是命令名，说要做什么；后面跟参数（argument），交代对谁做、怎么做。像喊「把报表拷到备份文件夹」：拷是命令，后面跟的是对象和去向。结构看懂，AI 的命令就能读个大概。

scp outline.pdf server:/tmp/意思
scp命令名：往服务器传文件
outline.pdf参数：传哪个文件
server:/tmp/参数：传到哪台机器的哪个目录

常见命令，认脸熟就行。不用背，更不用自己敲，但要认得出：cd 是进目录，ls 是列出有什么，cp 是复制，mv 是移动或改名，rm 是删除——它最危险，终端里删了不进回收站。下面这张表，混个脸熟就够。

命令干什么
cd进入某个目录
ls列出当前目录里有什么
pwd显示自己现在在哪个目录
mkdir新建一个目录
cp复制文件
mv移动文件，或者给它改名
rm删除——不进回收站，慎用
cat把文件内容显示出来看
git管代码的版本和仓库
python3运行一个 Python 程序

命令的脾气：精确，但没确认。好处是可重复：同一条命令跑一百遍，结果一样。但它没有二次确认弹窗，敲错一个字母，可能就是另一件事。AI 报命令时，你重点看两样：动的是哪个文件，有没有删除、覆盖这类回不来的动作。

1先看命令名：它要做什么
↓
2再看参数：动的是哪个文件
↓
3有删除、覆盖，先喊停再确认

4对应到你的项目：真跑过的命令

下面这些不是例子，是在你的项目里真被执行过的命令。以后 AI 再报出类似的，你就知道它在干什么：

git push把改动推上 GitHub 仓库，这门课就是这么交付的
node test_web.js跑 CANLink 的网页自测，改完先过一遍
python3 build.py生成刷写包自助站的网页
scp …往新加坡那台服务器传文件
ssh …登录那台服务器
curl …看一个网址通不通、返回什么

看出规律没有：命令名都是动词，参数都是名词——做什么、对什么做。抓住这两样，一条命令的意思就猜出八九成。

5和 AI 协作时怎么用

可以这样说「你打算跑哪条命令？先原样写出来给我看一眼，再执行。」
可以这样说「这条命令会动哪些文件？里面有没有删除或者覆盖？」
可以这样说「跑完了把结果的关键几行贴给我，别只说『成功了』。」
别这样说「你直接弄吧，弄完告诉我一声。」——命令没有确认弹窗，等它跑完，删错的可就回不来了。

7小测（选完立刻看对错）

1. 命令 python3 build.py 里，哪一部分是参数？
解析：python3 是命令名，意思是「用 Python 来跑」；build.py 是参数，告诉它具体跑哪个文件。
2. 哪个命令最该小心，因为删掉的东西不进回收站？
解析：rm 在终端里是直接删除，没有回收站兜底。看见它，先确认删的到底是什么。
3. ls 是干什么的？
解析：ls 是 list（清单）的缩写。进了一个目录先 ls 看看有什么，是 AI 干活的常规起手式。
4.（情景）AI 说：「我执行了 rm 把旧目录清掉了。」你的第一反应应该是？
解析：终端删除不可恢复。出事之前先确认对象和备份，比事后追问有用得多。
5. AI 汇报「刚执行了 git push」，它刚做完的是什么？
解析：push 是「推」：把本机的改动送到远程仓库。代码的同步和备份，都靠这一步。
