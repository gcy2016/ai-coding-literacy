AI 编程通识课 · 模块 1 程序是什么
第 01 节

代码是怎么跑起来的

1 一句话结论
代码是菜谱，厨师照着一步步做，菜才出锅。

2先打个比方：菜谱与厨师

菜谱写得再详细，也不会自己变成一盘菜——得有厨师照着一步步做。代码和机器就是这关系：代码是写给机器的菜谱，机器是厨师，一步一步照着执行，你最后看到的画面和结果，就是出锅的菜。中间还有个讲究：厨师只认一种「语言」，菜谱得先翻译成他能懂的版本，翻译的方式有两种，就是这一节要讲的编译和解释。

图：源代码是菜谱，机器是厨师，运行就是做菜

3正文

源代码和机器码是两种东西。源代码（source code）就是你和 AI 看到的那份代码：人能读懂的文字，一行行写明让电脑做什么。但芯片只认机器码（machine code），是一串 0 和 1。人写的这份，必须先翻译成机器码才能执行。

源代码人能读懂的文字
机器码芯片能直接执行

编译：提前整份翻译。编译（compile）是把源代码一次性全译成机器码，生成一个能直接运行的文件，以后每次运行都用这份译好的。像把整本菜谱先译成中文出版，厨师照中文版做，不用次次现翻。C 语言就是这一路。

1写源代码
↓
2编译成机器码文件
↓
3随时拿来运行

解释：边翻译边执行。解释（interpret）靠一个叫解释器（interpreter）的程序，读一行、译一行、做一行，不生成独立的机器码文件。像厨师看外文菜谱，旁边有人一句句翻给他听。Python 和 JavaScript 都这样。

编译解释
何时翻译动手之前，整份译完一边运行一边译
产物生成机器码文件不生成，靠解释器现场读
例子C 语言固件Python、网页 JavaScript

语言没有高下，只有分工。C 离硬件最近，常写固件；Python 好读好写，常写脚本和工具；JavaScript 管网页上的动作。HTML、CSS 严格说不算编程语言，一个管网页有什么、一个管长什么样。

语言主要管什么怎么跑
C固件、贴近硬件的程序编译
Python脚本、数据处理、工具解释
JavaScript网页上的交互动作解释
HTML / CSS网页的结构与样式浏览器直接处理

4对应到你的项目

旅行相册：解释型。相册是 HTML、CSS、JavaScript 写的，浏览器拿到代码直接读着跑，没有提前编译这一步，所以改完一刷新就能看到效果。

PNG2PPT：也是解释型。它以 Python 为主，靠 Python 解释器一行行执行，同样不用编译。

CANLink：一半一半。它的网页部分是 JavaScript，浏览器里解释执行；而盒子里跑的固件 vdlink 是 C 语言写的，必须先编译成机器码文件，再刷进芯片——刷进去的永远是机器码，不是源代码。

刷写包自助站：脚本生成。它的网页不是手写的，是一个叫 build.py 的 Python 脚本把数据「生成」出来的。改内容时改的是数据和脚本，再重新生成一次。

5和 AI 协作时怎么用

可以这样说「这东西是什么语言写的？改完是直接能跑，还是要先编译、重新生成一遍？」
可以这样说「你改的是源代码吧？真正跑起来的那份，更新了没有？」
可以这样说「报错出在哪一步：翻译（编译）阶段，还是运行阶段？」
别这样说「你不是改完了吗，怎么还打不开？」——没说哪个程序、卡在哪一步，AI 只能从头猜。

7小测（选完立刻看对错）

1. 电脑芯片能直接照着执行的是哪一种？
解析：芯片只认机器码。源代码必须先经编译或解释翻译过去，它才动得了。
2. C 语言写的固件改了一行，要让盒子用上新代码，必须先做什么？
解析：C 是编译型语言。刷进芯片的永远是编译好的机器码文件，源代码刷进去芯片也读不懂。
3. 一个 Python 脚本在甲电脑上跑得好好的，拷到乙电脑上双击没反应。最可能的原因是？
解析：解释型语言靠解释器现场翻译执行。没装解释器，脚本就只是一份没人念的菜谱。
4.（情景）AI 回复你：「vdlink 固件的源码我改好了，你直接刷这个 .c 文件就行。」这句话哪里不对？
解析：.c 文件是给人看的源代码，芯片只认编译后的机器码。编译这一步跳不过去，谁说能跳谁就说错了。
5. 网页改完一刷新就生效、不用先「生成」一遍，是因为？
解析：JavaScript 是解释型，浏览器边读边执行，所以改完刷新即见效。这也是网页开发调试快的原因之一。
