第 06 节

逻辑：判断、循环、函数

1 一句话结论
判断决定走哪条路，循环负责重复，函数把活打包。

2先打个比方：岔路口和机器

程序干活的方式，拆开看就三种动作：走到岔路口，按条件选一条路，这是判断；同一件事来回做很多遍，这是循环；把一整套工序封进一台机器，投料进去、成品出来，这是函数。流程图里判断画成菱形，正是因为它永远只有两个出口：是，或者否。

图：判断分岔，函数打包

3正文

判断：岔路口。判断（if，英文就是「如果」）的写法是「如果条件成立，就做某事」。条件只能回答是或否：「这个区域有照片吗？」有就点亮，没有就过。没有中间答案，这是程序和人商量事情最大的不同。

循环：不知疲倦的重复。循环（loop）把同一段处理重复执行。最常用的是 for：把列表里的东西一个一个取出来处理。几千帧报文、几百张照片，人看一眼就烦，循环过一遍只要一眨眼。

逐个取列表有几个取几次
同一套处理每个都这么办
不用人守它自己跑完

函数：打包好的机器。函数（function）把一段代码封起来，起个名字。给它输入（参数，parameter），它加工完吐出输出（返回值，return value）。同样的活要用十次，就调用十次，不用把代码抄十遍。

缩进和括号：谁归谁管。Python 靠缩进分段：缩进对齐的行归上面那句管。你以前学的 C 语言靠大括号圈地盘，意思一样、形状不同。AI 改代码时把缩进挪错位，逻辑会悄悄变样，这是验收时值得扫一眼的地方。

PythonC 语言
怎么分段靠缩进对齐靠大括号 { }
判断写法if 条件:if (条件) { }
形状印象干净，靠站队严实，靠圈围

4对应到你的项目：相册怎么点亮区域

相册每次打开，都会跑一段真实逻辑，正好是这一节的完整例子：它把全部区域挨个过一遍（循环），逐个检查这个区域下面有没有照片或者备注（判断）；有，就把这个区域标成「点亮」，并记下点亮的日期。

几百个区域谁亮谁不亮，全是这一遍循环加判断算出来的，没有谁手工点。你后来看到的时间线、地图上的亮暗，也都建立在这一次计算的结果上。

5和 AI 协作时怎么用

可以这样说「先把这段逻辑用分步骤的大白话讲一遍，我确认逻辑对了你再写代码。」
可以这样说「这个判断的条件到底是什么？条件不成立的时候，走哪条路、做什么？」
别这样说「逻辑你自己定，怎么快怎么来。」——判断条件就是业务规则，定错了，代码跑得再顺结果也是错的。

7小测（选完立刻看对错）

1. 用 for 循环处理一个装了 300 张照片的列表，循环里的处理会执行多少次？
解析：for 是逐个取、逐个处理，列表里有多少个就执行多少次。
2. 写法 count_city(photos, "重庆") 里，"重庆"扮演什么角色？
解析：括号里递进去的是参数；count_city 才是函数名；函数最后吐出的数字是返回值。
3.（情景）你让 AI 改相册的点亮规则，改完后所有区域全亮了。最先怀疑哪里？
解析：全亮说明「有照片才亮」这个条件形同虚设，先查判断条件，再谈别的。
4. Python 里，「点亮」这一行缩进着写在「if 有照片:」的下面，这个缩进表示什么？
解析：Python 用缩进表示从属关系，缩进错位，逻辑就会跟着变。
5. 同一段「挑某个城市照片」的代码，三个页面都要用。最好的做法是？
解析：函数打包一次、到处调用；将来改规则，只改这一处，三个页面同时生效。

8读代码：数一数某个城市有几张照片

下面这段 Python 是教学示例：一个函数，遍历照片列表，挑出属于某个城市的计数。点任意一行，看这一行在干什么。

def count_city(photos, city):
n = 0
for p in photos:
if p["city"] == city:
n = n + 1
return n
photos = [{"city": "重庆"}, {"city": "武汉"}, {"city": "重庆"}]
print(count_city(photos, "重庆"))
点任意一行，这里会显示这一行的中文解释。
